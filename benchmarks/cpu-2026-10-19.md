# CPU quotient-loop benchmark, 2026-10-19

Intel Core i7-7700, Windows, four OpenMP threads. Both versions were built
with MSVC 2022, `/O2 /std:c++20 /openmp /EHsc /utf-8`. A shared compatibility
shim mapped the existing GCC-style popcount/prefetch calls to MSVC intrinsics.

Baseline: commit `9b9d17b`, before the sieve and quotient-loop optimizations.
Optimized version: commit `edeb00d`, the SSE2 quotient-loop update.

Inputs through `10^15` use the median of three sweeps, alternating version
order. Each process first warms up with `M(10^8)`. Samples through `10^5`
average 100 calls. The `10^16` comparison is one run per version, rather
than a median. All answers matched between versions; both returned
`M(10^16) = -3195437`.

The code path through `10^5` is unchanged; those small timing differences
should not be attributed to an algorithmic improvement. Gains at larger
inputs vary with the direct-sieve cutoff, cache behavior, and sieve memory
cap. These measurements do not establish a fixed speedup or linear scaling.

The initial isolated SSE2 experiment against `6d44be8` also reduced
`10^14` from 3.900/3.906 s to 3.082/3.233 s in two alternating comparisons.
The full table above includes both the earlier sieve improvements and SSE2.

Repeat a sweep with the current benchmark CLI:

```sh
./bench_dr --benchmark 15 4 3
```

To compare the quotient backends alone, rebuild the current source with
`-DMERTENS_USE_SSE2_DIV=0` for the scalar version, keeping all other flags
and tuning settings the same.
